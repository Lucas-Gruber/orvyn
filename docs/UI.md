# Workspace interface

The workspace has a persistent sidebar, a collapsible page hierarchy, breadcrumbs and a document area. Creating a page opens and focuses its title immediately. Title changes save on blur or after a short pause; navigation waits for pending title writes and acknowledged document changes. A failed save keeps the current page open. Concurrent title changes offer an explicit choice to use the saved title or keep the local title, and block navigation until resolved. Closing a tab with an unsaved title or unacknowledged document changes prompts the browser's unsaved-changes confirmation.

Workspace search (`Ctrl/Cmd P`, or `Ctrl/Cmd K` outside the document editor) searches titles and saved document text across authorized spaces. It shows plain-text excerpts with highlighted terms and filters for space, content type and titles-only search. Results use the same inherited permissions as opening a page; trashed/inaccessible pages are excluded before ranking and pagination. Arrow keys choose a result, Enter opens it, and Previous/Next browse larger result sets. The open search refreshes every five seconds and on window focus, clears results on failure, and ignores responses for an older query/filter state. Its input stays anchored as result counts change. [SEARCH.md](SEARCH.md) describes indexing and current boundaries. The URL identifies the current space and page, so reloading or returning through browser history opens the same authorized page.

The sidebar shows favorites and recent pages. Only their IDs are stored in per-account device preferences; labels come from the current authorized page list. These preferences are not yet synchronized across devices. Pages outside the currently loaded sidebar batch can be found through search or by loading more pages.

The document editor supports slash commands and internal links to documents and stable headings; Ctrl/Cmd K inside the editor opens the link picker (see DOCUMENT_LINKS.md). Page actions contain width, attachments, history, permissions, move and trash operations. New databases and spaces use dialogs. Database views retain real filters, sorting, property editing, pagination, live updates, record pages and imports/exports. Person, multi-select and attachment fields use searchable multiple-choice popovers. Board cards have both drag controls and a keyboard-accessible status selector.

## Design system

- Semantic CSS tokens in `apps/web/app/assets/css/app.css` define Cybercade, Graphite, Midnight, Nord, Carbon, Matrix and Light. Appearance changes apply immediately and persist on the current device.
- Inter Variable and JetBrains Mono Variable are bundled locally. Font and Lucide licenses are in `apps/web/public/licenses`.
- `UiDialog` uses native modal dialogs with focus containment, Escape and focus return. Parent-driven closes consume their queued native event, so quickly reopening a dialog does not close the new opening. `UiMenu` supports arrow keys, Home/End, Escape and outside dismissal. `UiMultiSelect` uses the native popover layer and selectable options with selected states.
- The hierarchy supports arrow-key navigation and expansion. On small screens, navigation becomes an overlay and the obscured area is inert. Motion respects the operating system's reduced-motion preference.
- Existing records and pages are the only product content. The authentication illustration is decorative. Empty, loading, disconnected, read-only and failure states reflect actual application state.

## Verification and current boundaries

`tests/ui-workflow.test.mjs` exercises creation, title autosave and conflict recovery, hierarchy navigation, moves, trash/restore, search, favorites, deep links, all seven themes and mobile navigation in Chromium. Existing browser tests cover account management, uploads, five database views, live Kanban, people/files properties, linked databases and CSV transfer. Screenshots are written to ignored `.local/ui-review/` during these tests.

The interface is currently English. Full localization, synchronized preferences, whiteboards and public sharing remain unfinished product requirements. A complete assistive-technology and cross-browser audit is still required.

## Editor and database interaction

Markdown heading input supports H1–H4 and keeps an empty editable text position, with a faint `#`, `##`, `###` or `####` gutter marker, an empty-heading hint and a text-style selector behind the Format control. The Format control shows the current heading level even when its tools are collapsed. Levels are available through Markdown, slash commands, the selector and `Ctrl/Cmd Alt 1` through `4`; changing the level preserves the heading anchor. The heading permalink button is inserted only once a heading has content. The slash menu puts basic text blocks first and gives every command an icon and description.

Records open in a side peek by default. The row menu, right-click menu and keyboard actions also offer a center modal or full page. Each saved view can choose its default opening mode. Peek URLs survive reload, and switching between side and center keeps the same editor instance. Both peeks expose the real document, editable properties, comments, appearance, attachments and template actions. Navigation, save state and formatting controls live in the page header. A wrapping 40px title leads into compact 14px property rows, one separator and the 16px document. Property and document regions retain accessible names without visible form-section headings. Backlinks and attachments remain collapsed below the document. Empty fields share an Empty label; an empty date opens its date input on demand. Select/status fields display their saved option as a chip while retaining native selection and keyboard behavior. The mobile peek fills the screen with a 32px title, and changing peek mode preserves focus. Closing, opening another record or expanding to a full page waits for pending property, title and document writes; failed property drafts remain available for explicit retry/discard. Unsaved page titles, property drafts and unacknowledged document changes participate in the browser's unload warning.

Editor save state and the Format toggle appear in the page header, leaving document content at the top of the editor surface. In peeks and narrow windows, the saved-state text has an accessible label and tooltip beside its icon; disconnected/saving states remain announced. Formatting tools are collapsed initially; opening them reveals separate groups for block type, links, emphasis, lists/code and undo/redo. Slash commands, shortcuts and selection formatting remain available independently. Appearance controls are revealed on page hover, keyboard focus and touch. Existing theme preferences are preserved. [Reference review](UI_REFERENCES.md) records the sources and limits of the Notion comparison.

Database search and actions share the view bar, followed directly by the table. Narrow database surfaces wrap the views and tools into separate rows. Record creation buttons wait for an active database write instead of accepting a click that cannot run. Table headers have field-type icons and rows expose action buttons on hover/focus (always on touch). Adding a property uses a dialog with the same spacing as other forms. Multi-select changes commit when the picker closes, so removing the last matching value does not remove a filtered row halfway through choosing. Native popovers keep pickers and context menus above dialogs. Sidebar page context menus provide supported opening, copy-link and subpage actions; Shift-right-click retains the browser menu.

**Keyboard shortcuts** in the sidebar lists the supported keys with platform-specific labels. The editor retains its formatting, Markdown, undo and block/hierarchy shortcuts. Workspace actions include search (`Ctrl/Cmd P`, or `Ctrl/Cmd K` outside the editor), sidebar toggle (`Ctrl/Cmd \\`), new page/database (`Ctrl/Cmd Alt N/D`), theme toggle (`Ctrl/Cmd Shift L`) and shortcut help (`Ctrl/Cmd /`). Databases support new record (`Ctrl/Cmd Alt R`), view settings (`Ctrl/Cmd Alt F`), search focus (`/` outside a text input), center peek (`Shift Enter`) and full-page opening (`Ctrl/Cmd Enter`) on a focused record. Arrow keys navigate menus/tabs; `Shift F10` opens a focused item's context menu. `Ctrl/Cmd Enter` submits dialog forms outside a rich-text editor.
