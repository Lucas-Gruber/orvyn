# Workspace full-text search

Open **Search** in the sidebar, `Ctrl/Cmd P`, or `Ctrl/Cmd K` outside the editor. The default searches page titles, saved document text and stored database property values across the signed-in user's authorized spaces. Controls filter by space, page/folder/database/record type, titles, document text or database properties. Property matches open the normal record page and show a bounded, highlighted excerpt with the field's label.

Queries use PostgreSQL's `simple` text configuration with an AND of word prefixes. Matching is case-insensitive, preserves accents and supports German/English text without imposing one language's stemming rules. With All content selected, terms can occur across titles, document text and stored properties; an exact literal substring in the title also matches. Explicit scopes require a match in that scope. Exact titles precede other title matches, followed by content/property matches; weighted full-text rank (title, then document, then properties) and current modification time break ties. Percent/underscore characters in title searches are literal. Phrase operators, arbitrary substrings in property values, fuzzy matching and language-specific stemming are not implemented.

Searchable properties include Text, Number, Select, MultiSelect, Status, Date, Checkbox, URL, Email and Phone. Selection fields index current option labels rather than internal IDs; MultiSelect serves as searchable tags. Nonempty fields include their current property name in the excerpt/index. Configured CreatedTime and LastEditedTime fields index UTC timestamps. Missing/deleted fields and removed options contribute no text; restoring a property restores its retained, currently valid values. Person, Files, Relation, Formula, Rollup and identity metadata remain excluded: resolving or caching their contents could copy external identities, file names or actor-dependent data into another search result. Referenced records and their own fields can still be searched independently when currently readable.

Property vectors treat angle brackets as word separators so PostgreSQL's HTML-aware tokenizer does not discard text literally written inside script tags. Previews normalize whitespace, retain the authored text characters and render as escaped text. Property results show matching fields joined by a middle dot, rather than a dump of unrelated record metadata.

Results contain bounded, plain-text excerpts and character ranges for highlighting. The browser renders those ranges as escaped text, never HTML. Markup typed into a code block remains literal. The query uses server-side cursor pagination after authorization, so hidden pages neither fill a page nor contribute to a reported total. The UI shows one page of up to 30 results, supports keyboard navigation and does not fetch entire documents for its previews. Its open results refresh every five seconds and on focus/visibility return; closing/sign-out clears component state. Requests for older query/filter/cursor states are canceled and ignored. Clicking a result still opens the page through the normal access checks and pending-write navigation flow.

## Projection and migration

Migration 34 creates a separate `page_search` projection with GIN full-text and trigram title indexes. Migration 39 adds `property_text`, scope-specific document/property GIN vectors and a combined weighted vector. PostgreSQL must provide the standard trusted `pg_trgm` extension; the repository's PostgreSQL container includes it. Both migrations backfill the projection while preserving source page/revision/record content, versions and modification timestamps.

An insert or title/document update on `pages` updates the projection in the same transaction. Record value writes, schema/option edits and metadata timestamp changes refresh stored property text transactionally. REST writes, collaborative durable writes, CSV imports, reciprocal relation writes and template application therefore share the same index path. Schema changes rebuild only their database's property projection; unchanged projection text is not rewritten. Unacknowledged/offline edits are not searched. Source document sizes/structure are bounded by the editor schema; the index includes the complete permitted text rather than a truncated prefix. Large-schema/index rebuild load testing remains outstanding.

Extraction reads authored `text` and `content` nodes, joins adjacent formatting spans and separates blocks. It does not resolve node attributes, people, attachments, dynamic document previews or linked databases into copied content. Source snippets never inherit the contents of an inaccessible referenced page. The projection is an internal table, not additional columns serialized by existing page APIs. Trash retains its projection for restoration; every read checks current access, including ancestor trash/restrictions and current space membership.

## API

`GET /api/v1/search` continues to return an array of page metadata, adding `match_source` (`title`, `content`, `properties`, `mixed` or `recent`), `excerpt` and `highlights`. Optional parameters are `q` (up to 200 characters), `spaceId`, `kind`, `scope=all|title|content|properties`, `limit` (1–100, default 40) and `after`. The properties scope returns record pages only, including when the query is empty. A next page is advertised only through `X-Next-Cursor`; there is no hidden/global result count. Cursors retain exact PostgreSQL microsecond timestamps and are bound to the query/filter state. Each page is evaluated against current permissions. Results are mutable as documents or permissions change, rather than a frozen search snapshot. Responses use `Cache-Control: private, no-store`.

Document/heading link pickers and related-database selection explicitly use `scope=title`, preserving their title-focused behavior. Binary attachment contents, comments, reference/computed property values, identity metadata and historical revisions remain outside this index.
