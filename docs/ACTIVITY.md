# Workspace activity

Open **Activity** in the sidebar for the current space, or **Page actions → Page activity** for one page/record/database. The timeline records page creation/document edits/title/appearance/access/moves/trash/restore, discussions and moderation, attachment upload/removal, database schema/view changes and record creation/updates/imports. Entries open their current page. Space appearance/creation is visible to space readers; invitation, membership and team-conversion events require current Admin/Owner rank.

Migration 27 begins this history. Older security audit rows have no entity references and cannot safely be assigned to pages retroactively. Security/authentication auditing remains separate. Activity rows contain the source space/page, actor ID, action kind and timestamps. They do not copy page titles, document bodies, comment text, property values, filenames, invitation addresses or other payloads. Page labels/icons and actor emails resolve from current authorized sources; a former space member is displayed as **Former member**. Rename entries use the current page title, while page revisions retain separately authorized document/title history.

Each activity write belongs to the same transaction as its source action. Rejected/conflicting/rolled-back writes leave no entry. Collaboration creates entries only after validating the candidate update and alongside durable document state/revisions. Document edits by one actor on one page share fixed five-minute windows. This coalesces timeline entries while preserving every accepted durable document update and acknowledgement. Entries keep their first creation position; the latest edit time is available in the timestamp tooltip.

Record activity is scoped to the record page rather than announced on its parent database. CSV import records one event per imported record, without a parent-level record-count summary. Folder sibling-rank maintenance adds no extra events. Current inherited page access, membership, ancestor restrictions and trash determine which entries can be read. A trashed page's history disappears until it becomes readable again. Page-less administrative events have explicit minimum ranks. Feed cursors are scoped to the space, optional page and currently visible entries; inaccessible cursor IDs cannot expose hidden activity positions.

`GET /api/v1/spaces/:id/activity` accepts an optional `page` UUID, a `before` cursor and `limit` (default 40, max 100). Reads hold a shared space lock while authorization and the query run. Missing/inaccessible spaces/pages use not-found responses. There is no hidden/global total. The UI refreshes the first page every 15 seconds while open and visible; loading earlier entries pauses automatic replacement until manual refresh. Account/space changes clear panel state. Existing revision history remains a separate control.

This is a high-level activity timeline. Per-field before/after diffs, historical display-name/title snapshots, saved activity filters, subscriptions, push delivery and a dedicated instance security-audit UI are separate work. APIs added later should attach a page/space target to `audit()` or call the transactional activity function, with record-level scope for private record actions.

Tests exercise actual committed operations, stale-write rollback, edit coalescing, current labels without body copies, scoped pagination/cursors, former members, current role/trash/restriction checks, private-record isolation, two-replica edits and rejected updates. Chromium covers space/page timelines, navigation, responsive width and clearing revoked page content.
