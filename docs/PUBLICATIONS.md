# Public page snapshots

Admins and owners can use **Share → Publish** on document, folder, database and whiteboard pages. Select individual pages, optionally select additional attachments, review the exact snapshot and then publish. Subpages and embedded targets are never selected implicitly. A public reader can follow links and heading anchors only to included pages. Creating these links does not change authenticated page permissions.

Each link is an independent, read-only snapshot. Edits, new subpages, changed covers and new attachments remain private until a fresh review is published. Updating a publication retains its URL; the signed preview includes its current version. Password protection, expiry, search indexing (off by default), temporary disabling and permanent revocation are supported. Password-protected links cannot opt into indexing. Permanently revoked links require a fresh review and a new URL.

The preview lasts ten minutes. Delayed choice-list responses preserve the reviewed scope when the actual selection is unchanged. Property catalog refreshes preserve an unchanged selection order.

Source content/version, file identities, chosen settings, actor and publication version are bound to a signed digest. Publishing locks source spaces in stable order, rechecks current publish permission for every source and rejects stale previews. Request receipts make concurrent/lost-response retries idempotent, including after a later update. Audit/activity events require admin access.

Public links use random 256-bit URL tokens. Only their hashes and authenticated encryption are stored. Passwords use independent scrypt salts; successful entry grants a signed, HttpOnly, SameSite=Lax cookie for at most eight hours or the link expiry. Updating, disabling or re-enabling a link invalidates older password cookies. Unlock attempts have a bounded hashed token/IP rate limit. Anonymous users gain no write, comment, private API or collaboration access.

Permission, inheritance, hierarchy, trash/deletion, publisher membership and space ownership changes revoke affected publications. Ancestor changes also revoke descendant sources. Restoring the former permission does not revive an old link. Every public read and attachment read also checks current source existence and the publisher's current admin/owner access. File grants are tied to exact immutable, ready file identities; deleting an attachment makes its public download unavailable. Private object-store URLs are not exposed.

The published projection contains normalized document content and visible whiteboard elements, never Yjs history, deleted canvas elements or arbitrary element metadata. Person mentions become anonymous text. Unselected internal links lose their link target; unselected page/whiteboard/database blocks and unavailable file blocks become generic placeholders. Approved page-owned images/files are included when referenced by the selected page; foreign files require their page to be selected or an explicit attachment selection and independent publish authority. Extra attachment names are explicitly reviewed. Original image upload filenames are replaced with generic names unless deliberately selected as additional attachments. No unrelated ready files, parent/space names, comments, member directory or author email addresses are copied.

The public route `/s/<token>` uses a separate safe Vue renderer. It supports heading levels 1–4 and stable anchors, formatting, lists/tasks, code, quotes, callouts, toggles, tables/widths, columns, images/downloads, page previews, opt-in provider video and read-only Excalidraw canvases. It does not mount the authenticated workspace or connect to its APIs/WebSockets. HTML metadata is generated from the approved snapshot; locked links reveal no source title/content in their initial HTML. Pages and API/file responses use no-store and no-referrer. An open reader rechecks access on focus/visibility changes and every 30 seconds while visible; revocation clears the rendered snapshot. Previously received/copied bytes cannot be recalled.

Multi-page publications use a collapsible hierarchy with local title search, active-page breadcrumbs and a mobile page picker. Navigation includes only approved snapshot pages. Ancestors are resolved from the snapshot; malformed parent cycles are bounded and cannot hide approved pages. Expanded branches follow the active page. Snapshot review uses the same navigation without leaving the private workspace. The public header remains visible while scrolling.

The publish dialog assigns one request ID to each reviewed snapshot. A lost response or temporary server failure retries that same request once. If confirmation is still unavailable, the dialog retains the exact review and request ID for **Retry publication**; receipt checks return the existing link instead of creating a second one. Closing an uncertain review refreshes the link list. Permission/staleness failures require a new review and do not retry a changed snapshot.

Bounds: 100 rendered pages, 20 databases, 500 selected database records, 250 approved files, 100 MiB of attachment payloads and 10 MiB of snapshot JSON per publication. Publish choices are searchable across spaces where the actor can publish. The page always remains selected. Additional file selection in the current UI lists unattached files on that page; the API also permits explicit authorized cross-page file selections.

Database publications choose one saved view per database, an explicit set of up to 500 total records and an explicit subset of that view’s visible properties. Title is required; board grouping and calendar date fields are required by those views. The snapshot retains the saved filter/sort result, chosen property order/widths and only used option labels. New records, hidden fields, private relation targets and unrelated file/cover previews are excluded. Every selected row independently requires admin/owner access, even when its page body is not published, and becomes a revocation source. Database schema, view and record revisions participate in preview freshness.

Selecting rows publishes their approved property values; it does not publish their document text, icon or cover. **Also include these items’ page text** explicitly includes the selected record pages and their referenced blocks/files/covers, within the separate 100-page limit. Files properties include only approved ready files owned by that record; their filenames and download grants appear in the review. Relation values include only target records selected elsewhere in the same publication. Person/CreatedBy/LastEditedBy identities and Formula/Rollup calculations remain unavailable until their public dependency model is implemented. Authored Email/Phone fields and explicit time properties can be selected and reviewed.

Public databases have read-only Table, Board, List, Calendar and Gallery views, scoped record dialogs, approved-file image previews, calendar navigation and links to explicitly included record documents. Dialogs never request a private record body. Snapshot review navigation remains within the reviewed content instead of leaving for the private workspace. The private scope picker uses permission-checked view queries that return only record IDs and titles, searchable/paginated choices and separate selection of record bodies.

Individual record pages have a separate property selection in **Share → Publish**. Their snapshot includes their own content and only the checked active properties, without publishing the parent database, its name, saved views, siblings or schema configuration. Related records can be added explicitly as separate record pages. Direct record selection is independent of saved-view filters; database-view publication still enforces its own visible-field boundary and filters. Title remains required. Person/creator/editor identities and calculations keep the same exclusion policy. Parent database and record permissions remain revocation sources even when the database is not published. Records shared both in a database view and as a separate page retain their independently reviewed property selections.

Remaining: public calculation/identity dependency policy, configurable/white-label public appearance, custom domains, social preview images and operational/load testing. Individual record pages can also be published directly through their own share dialog. Search engines honor indexing directives voluntarily; noindex is not access control. Public previews do not deploy or expose a cloud development environment.

Validation covers review freshness/tampering/actor binding, concurrent idempotent retries, explicit scope and legacy anchors, source/ancestor/publisher revocation, password cookies and origin checks, expiry/disable/update/revoke, explicit file grants, deleted/unknown whiteboard metadata, anonymous browser navigation, password-gated HTML, private request/WebSocket isolation, focus-time revocation, mobile layout, all five database views, record body exclusion/opt-in, hidden property/option isolation, source-row permissions, file/relation grants, 205-row pagination, saved-filter checks, nested/local navigation, mobile picker keyboard behavior and automatic/manual recovery after lost publication responses, direct record publication without parent/sibling metadata, independent property scopes, saved-filter independence and shared-record links. Screenshots are generated from disposable browser fixtures, not product-seeded data.
