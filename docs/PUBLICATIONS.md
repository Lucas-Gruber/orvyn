# Public page snapshots

Admins and owners can use **Share → Publish** on document, folder and whiteboard pages. Select individual pages, optionally select additional attachments, review the exact snapshot and then publish. Subpages and embedded targets are never selected implicitly. A public reader can follow links and heading anchors only to included pages. Creating these links does not change authenticated page permissions.

Each link is an independent, read-only snapshot. Edits, new subpages, changed covers and new attachments remain private until a fresh review is published. Updating a publication retains its URL; the signed preview includes its current version. Password protection, expiry, search indexing (off by default), temporary disabling and permanent revocation are supported. Password-protected links cannot opt into indexing. Permanently revoked links require a fresh review and a new URL.

The preview lasts ten minutes. Source content/version, file identities, chosen settings, actor and publication version are bound to a signed digest. Publishing locks source spaces in stable order, rechecks current publish permission for every source and rejects stale previews. Request receipts make concurrent/lost-response retries idempotent, including after a later update. Audit/activity events require admin access.

Public links use random 256-bit URL tokens. Only their hashes and authenticated encryption are stored. Passwords use independent scrypt salts; successful entry grants a signed, HttpOnly, SameSite=Lax cookie for at most eight hours or the link expiry. Updating, disabling or re-enabling a link invalidates older password cookies. Unlock attempts have a bounded hashed token/IP rate limit. Anonymous users gain no write, comment, private API or collaboration access.

Permission, inheritance, hierarchy, trash/deletion, publisher membership and space ownership changes revoke affected publications. Ancestor changes also revoke descendant sources. Restoring the former permission does not revive an old link. Every public read and attachment read also checks current source existence and the publisher's current admin/owner access. File grants are tied to exact immutable, ready file identities; deleting an attachment makes its public download unavailable. Private object-store URLs are not exposed.

The published projection contains normalized document content and visible whiteboard elements, never Yjs history, deleted canvas elements or arbitrary element metadata. Person mentions become anonymous text. Unselected internal links lose their link target; unselected page/whiteboard/database blocks and unavailable file blocks become generic placeholders. Approved page-owned images/files are included when referenced by the selected page; foreign files require their page to be selected or an explicit attachment selection and independent publish authority. Extra attachment names are explicitly reviewed. Original image upload filenames are replaced with generic names unless deliberately selected as additional attachments. No unrelated ready files, parent/space names, comments, member directory or author email addresses are copied.

The public route `/s/<token>` uses a separate safe Vue renderer. It supports heading levels 1–4 and stable anchors, formatting, lists/tasks, code, quotes, callouts, toggles, tables/widths, columns, images/downloads, page previews, opt-in provider video and read-only Excalidraw canvases. It does not mount the authenticated workspace or connect to its APIs/WebSockets. HTML metadata is generated from the approved snapshot; locked links reveal no source title/content in their initial HTML. Pages and API/file responses use no-store and no-referrer. An open reader rechecks access on focus/visibility changes and every 30 seconds while visible; revocation clears the rendered snapshot. Previously received/copied bytes cannot be recalled.

Bounds: 100 selected document/folder/whiteboard pages, 250 approved files, 100 MiB of attachment payloads and 10 MiB of snapshot JSON per publication. Publish choices are searchable across spaces where the actor can publish. The page always remains selected. Additional file selection in the current UI lists unattached files on that page; the API also permits explicit authorized cross-page file selections.

Remaining: database saved-view/record/property scope, richer hierarchy navigation, configurable/white-label public appearance, custom domains, social preview images and operational/load testing. Database and record pages are intentionally unavailable in the public publish tab until their separate projection and scope review are implemented. Existing authenticated permissions continue to work on record pages. Search engines honor indexing directives voluntarily; noindex is not access control. Public previews do not deploy or expose a cloud development environment.

Validation covers review freshness/tampering/actor binding, concurrent idempotent retries, explicit scope and legacy anchors, source/ancestor/publisher revocation, password cookies and origin checks, expiry/disable/update/revoke, explicit file grants, deleted/unknown whiteboard metadata, anonymous browser navigation, password-gated HTML, private request/WebSocket isolation, focus-time revocation and mobile layout. Screenshots are generated from disposable browser fixtures, not product-seeded data.
