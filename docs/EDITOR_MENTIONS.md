# People in documents

In an editable text block, type `@` and choose a current page reader. The slash menu also includes **Mention person**. Arrow keys/Enter choose; Escape dismisses. Code blocks keep `@` literal. Read-only viewers can see resolved references and open their inbox, while inserting a new person requires document edit permission. There can be at most 100 different people in one document; duplicate occurrences share one identity.

Document schema 9 adds an inline atomic `orvynPerson` node containing only a user UUID. Labels, emails, profile URLs and copied account metadata are not stored in the node. The renderer resolves only IDs actually referenced by the current saved document, within current page permissions. Current space membership and the target's current page access determine whether an email can be displayed. Lost/deleted/inaccessible identities render as **Person unavailable**. Resolution and selection markers do not rewrite the document.

Migration 26 adds a document-person projection and document-mention notifications. REST writes and the collaboration server validate newly added references against current page readers, under the same authorization locks used for document writes. Already stored references may remain after their target loses access so ordinary editing keeps working. A new foreign, unknown or inaccessible identity is rejected before persistence or broadcasting. Invalid updates pause the current collaboration connection and retain its unsaved local state; recovery by copying content/reloading remains necessary when an invalid reference was inserted during a rights-change race. Automatic removal/rebasing of rejected edits is separate work.

Projection replacement and inbox insertion happen in the same transaction as document state/revisions. The projection is deduplicated by page/person. New references notify a current reader except the author. Additional occurrences and ordinary text edits leave the notification's identity/read state alone. Removing the last occurrence removes its projection and notification; reintroducing it later creates a fresh notification. Revoked recipients cannot read/count/open old notifications until authorized again, and never receive new content through their inbox while access is absent.

Document notifications resolve the current page title and text excerpt rather than storing a copy. Opening from Inbox visits the page and highlights/focuses the first occurrence of the current user's reference. The source type is distinct from comment/reply notifications. Account display names, profile popovers, group mentions, cross-page reference navigation and a picker entry for document/heading links are not part of this people-reference slice; existing document/heading link commands remain available separately. Plain external clipboard serialization uses `@Person`; exporting current identity labels needs an explicitly permission-scoped exporter.

Identity metadata refreshes after a changed reference set has been saved and every five seconds while visible. Ordinary keystrokes do not request the identity directory repeatedly. Directory suggestions are bounded/debounced and search current readers only. Account changes/page unmounting clear local identity state. Comment mentions remain ordinary text plus chosen user IDs, as documented in NOTIFICATIONS.md.

Model/API/replica tests cover Yjs round-trips, stripped copied metadata, UUID/unique-person limits, current labels, historical references, rejected additions, mention deduplication, read-state preservation and no persistence/broadcast of invalid recipients. Chromium covers typing/keyboard choice, read-only labels, reload, inbox navigation/focus, permission changes, continued editing of historical references and mobile width.
