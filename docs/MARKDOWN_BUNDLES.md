# Markdown hierarchy bundles

Choose **Page actions → Export pages as ZIP** on a document or folder. The picker lists readable documents/folders beneath that starting page, with individual checkboxes, **Select all**, **Starting page only** and a refresh action that retains the remaining selection. The starting page is required. Review shows the resulting page/file paths, sizes and Markdown conversion notes before downloading. `Ctrl+Enter` / `⌘ Enter` reviews or downloads the current selection. Pending edits to the open document are flushed before review.

Up to 100 pages may be selected from the first 500 readable candidates. Traversal stops at other page kinds and inaccessible branches; database record data and whiteboard scenes are never implicitly copied. An unchecked intermediate folder/page does not get an exported name or file: its selected descendants move beneath their nearest selected ancestor. Each selected page uses `<safe title>/index.md`, with nested folders and added subpage navigation.

Internal links and preview blocks targeting selected pages use relative paths. Cross-page heading links use the same GFM-style anchors as the exported target, including duplicate labels and authored numeric suffixes. Single-file Markdown import/export share that anchor generator so collisions cannot silently change a link's destination. Links outside the selection remain authenticated Orvyn links when currently readable; inaccessible targets get generic text. Raw source IDs are omitted from the manifest and local paths. Authored text and deliberately linked outside pages retain their ordinary contents/URLs.

**Copy embedded images and files** is an explicit option, enabled in the browser. It copies only ready attachments referenced by selected documents, with an independent current read check on every attachment owner. Unreferenced catalog files, page covers and unavailable/private attachments are excluded. Copies are deduplicated by file identity and placed under the starting directory's `_attachments/`; Markdown uses relative paths. Unchecked attachments retain protected Orvyn download URLs. People default to `@person`; optional names resolve only current members who can still read each source page and may include account addresses.

The ZIP includes `README.md` and a versioned `manifest.json` describing exported page paths, selected parents, original titles/kinds, sizes and conversion notes. Filenames normalize Unicode, remove separators/control/bidi characters, avoid traversal and Windows device names, truncate at code-point boundaries, retain attachment extensions and resolve case-insensitive collisions. Directory paths are limited to 1,800 UTF-8 bytes. No source filename is treated as an extraction path; export never creates local directories or symlinks.

The uncompressed total, including Markdown and manifest text, is bounded to 32 MiB and 100 copied attachments. A page retains the single-file Markdown codec's own output bound. Oversized selections fail explicitly; files/pages are never silently truncated to fit. ZIP entries use a fixed timestamp and ordinary stored bytes with no executable/symlink attributes. The API limits concurrent bundle downloads to two per process and rate-limits previews/downloads. Object fetches have an overall 90-second deadline and destroy streams after cancellation, size mismatch or failure.

Review uses a repeatable-read snapshot and a digest over generated text, selection/options and private attachment metadata/object identities. Confirmation requires that digest, authenticates the current session and recalculates source, selected-tree, referenced-page, people and independent attachment access. File bytes come from their immutable upload object keys outside the SQL transaction. After reading them, the API checks session and the complete plan again before sending any ZIP bytes. Storage failure or mid-copy access/content changes return an ordinary error, never a partial archive. Responses use an attachment disposition and private/no-store caching; exporting does not create a public link or durable access grant.

This is a readable Markdown transfer, not a full backup or an automatic restore format. Database values/schema, whiteboard scenes, comments, history, permissions, icons and covers are not included. Markdown layout conversions follow MARKDOWN_EXPORT.md. Automatic hierarchy/attachment import, portable native JSON restoration and faithful Notion migration remain unfinished.

API (authenticated read access, JSON POST with exact Origin):

- `GET /api/v1/pages/:id/export/tree` → `{pages:[{id,parentId,title,kind,depth}],truncated}`. Root `parentId` is always null.
- `POST /api/v1/pages/:id/export/bundle/preview` with `{pageIds,includeAttachments?,includePeopleNames?}` → `{title,filename,digest,pages,files,bytes,warnings}`. Boolean defaults are false for programmatic clients.
- `POST /api/v1/pages/:id/export/bundle` with the same options and required `review:<digest>` → `application/zip`. A changed generated plan returns 409; unavailable selected pages return 404; failed attachment copies return 503. POST responses use the API's standard 201 status.

`tests/markdown-bundle.test.mjs` covers relative page/heading navigation, native anchor collisions, explicit scope/kind isolation, independent file permissions and exact copied bytes, people opt-in, fresh review/access checks, sparse selections, safe/colliding names and extensions, candidate/page/file/byte bounds, and real Chromium downloads with delayed tree/review responses, mobile layout and shortcuts. `tests/markdown-bundle-storage.test.mjs` holds an actual object-store GET through a local proxy, revokes membership while the copy is pending and verifies no ZIP is returned; it also checks missing-object rejection and attachment-free downloads.
