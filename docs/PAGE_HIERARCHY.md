# Folders and hierarchy placement

Create a folder from **Create in this space → New folder**, or a subfolder from the current page's actions. Folders share the page model, rich-text introductions, icons/covers, attachments, permissions, trash and links. Their content area lists accessible child pages and offers creation controls to editors. Folders do not create a separate permissions boundary.

In the sidebar, drag a page/folder to the top/bottom of another row to place it before/after that item. The center of a writable page/folder nests it inside. A line or outline indicates the destination; hovering over a collapsed parent expands it. The top-level drop zone moves an item to the space root. Database rows support adjacent placement; record pages stay in their database.

With a sidebar item focused, **Alt Shift Up/Down** reorders it among siblings; **Alt Shift Right** nests it in the previous writable page/folder; **Alt Shift Left** places it after its parent. The existing Move page dialog remains available, including on touch devices. Native touch dragging and cross-space moves are not implemented.

Reordering siblings leaves visibility/grants unchanged. Changing parent preserves the previous audience as explicit restrictions on the moved root; the new parent's restrictions can narrow access further. Moving requires edit access to every descendant and the destination parent. Cycles, inaccessible destinations, excess depth, cross-space movement, database/record parent violations and stale placements are rejected. Page IDs, rich documents and heading IDs are retained, so existing permanent links continue to resolve. The client waits for pending title/document saves before moving and maintains its active editor.

Migration 22 adds folder kinds, a separate `structure_version` and internal numeric `sort_rank` values. Placement uses a structure counter so unrelated text/title/appearance changes cannot overwrite or spuriously reject a hierarchy edit. An optional expected target parent catches a relative drop whose anchor moved since it was rendered. Legacy version/sortOrder moves remain supported. Legacy sort_order is preserved; current UI ordering uses sort_rank with deterministic fallbacks.

Ranks have gaps and use midpoints. When precision becomes tight, sibling ranks compact inside the same transaction and space lock. Internal-only rank updates do not change other pages' timestamps, access versions or database activity notifications, or increment space versions per hidden sibling. A same-parent placement increments the space version once. Tests verify these privacy boundaries. The visible tree builds adjacency maps and sorts sibling groups once rather than repeatedly scanning all pages for every displayed row. Pagination still bounds what is loaded; this is not a virtualized whole-workspace tree.

API tests cover independent versions, identity/content preservation, shared/restricted audiences, inherited descendant restrictions, cycles, root/relative placement, database boundaries, cross-space rejection, stale anchors and private rank compaction. Chromium tests create and nest real folders, use native drag and keyboard movements, follow permanent heading links, reload the order, verify read-only controls and check mobile overflow.
