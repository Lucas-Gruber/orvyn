# Whiteboards

Create a whiteboard from the space's creation menu, or use `/Whiteboard` in a document to select an existing canvas or create a child canvas. The document stores only the target page ID. Viewing/editing the document grants no additional access to the board. Embedded canvases start in preview mode, fit their drawing into the available width and expose explicit editing and full-page navigation. Standalone canvases retain the regular page hierarchy, title, permissions, attachments and activity.

The drawing interface embeds Excalidraw 0.18.1 through an isolated, lazy-loaded React adapter. It supports shapes, arrows, free drawing, text, frames, grouping, layering, per-user undo/redo, zoom/pan and authenticated live pointers. Keyboard handling stays inside the focused canvas. Local preferences such as camera position/selection are not shared. Browser fonts/assets are copied from the pinned package for local serving; the server-side Liberation font is excluded. Notices are in `apps/web/public/licenses`.

Images use private, sniffed PNG/JPEG/GIF/WebP attachments owned by the board. Data URLs stay in the browser and portable exports, not the persisted scene. Pasted/imported images are uploaded and rebound to new owned file IDs. Cross-board imports copy bytes independently. Existing image previews still require current page/file access. SVG uploads, arbitrary web embeds, generated HTML/AI frames and server-synchronized shape libraries are outside this slice.

PNG, SVG and portable `.excalidraw` exports are produced by the native drawing library. Version-2 Excalidraw files can replace the current drawing after a recovery checkpoint; their shapes/settings are validated and their image payloads are copied to private storage. Imports are limited to 35 MB before parsing, with existing per-file upload limits still authoritative.

Migration 42 introduces dedicated scene/state and revision tables. Hocuspocus uses the existing page UUID and authenticated session, choosing its document codec from the page kind. Whiteboards cannot be overwritten through the rich-document PUT route. Every incoming update is validated against authoritative stored state before acknowledgement/broadcast. Every outbound frame retains current access checks and revocation locks. Element objects use Yjs map conflict resolution; independent elements merge without replacing the whole canvas. Permissions, reconnect, two-replica persistence, hostile namespaces and read-only updates are integration-tested.

Scene schema 1 allows at most 2,000 elements (including retained tombstones), 1 MiB of serialized scene data and 2 MiB of encoded CRDT state. It bounds coordinates, nested payloads, text, points, style values and links. New image references must identify ready images owned by that board. Scene text updates the board's own search projection transactionally; embedding does not copy that text into another page.

Recovery history stores immutable prior-state checkpoints about every 30 seconds of activity. Import/restore explicitly checkpoint the current state first. History is paginated and permission checked; restoring creates new element revisions rather than replacing CRDT state behind connected clients. Pending drawing edits and uploads participate in navigation/unload protection. Losing edit access reloads authoritative state; losing read access clears the canvas.

Remaining work includes camera persistence, synchronized libraries, longer-running conflict/load tests, CRDT/tombstone compaction, touch/browser accessibility validation and richer previews of whiteboard text in generic page cards. The full product remains under development.
