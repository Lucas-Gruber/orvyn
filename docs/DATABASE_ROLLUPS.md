# Database rollups

Rollup properties calculate a read-only number from directly related records in the same space. Choose an existing Relation property, then Count records, Sum, Average, Minimum, Maximum, Count nonempty values or Count unique values. All calculations other than record count also select a compatible field in the target database. Click a rollup column heading to edit its name/configuration with optimistic schema-version checks.

Numeric aggregates accept Number fields and local numeric Formula fields. Nonempty/unique counts accept scalar fields and local scalar formulas. Target formulas may use local record fields, metadata and other local formulas; dependencies on Files, Relations or other Rollups are excluded. This keeps target-only invalidation tied to the directly related record/schema revision. Rollup chains, multi-hop relation formulas, original-value arrays and date extrema are not implemented. A source formula may use the numeric result of a rollup, for example `prop("Total hours") * 80`.

Every query recalculates from the current actor's readable relation projection. Private targets do not contribute to counts, sums, filters or exports. A readable database with no matching targets yields zero for counts/sum and null for average/minimum/maximum. Empty values are ignored by value counts and numeric aggregates; zero and false remain nonempty. A missing/inaccessible target database, removed field or incompatible changed target formula yields null. Numeric aggregates use numeric intermediates and return finite double-precision results; overflow produces null.

The server authorizes target schema lookup and configuration within the source space lock. Related schemas are held in a weak sidecar map and are never serialized in source metadata or exports. Queries compile a fixed aggregation allowlist and bind all property/database IDs. Calculations happen before server-side filters, sorts and pagination. Record mutation responses, CSV and JSON exports use the same values. Rollup results cannot be patched or imported; CSV mapping skips matching computed columns.

Live subscriptions include a rollup's Relation dependency even when that Relation column is hidden. Directly related record edits, schema changes and access revocation refresh loaded source rows across replicas. Later activity on already inaccessible targets sends no relation invalidation. As with relations/formulas, target-only changes to source records outside the currently loaded result/page can require refreshing to include newly matching records.

Validation: `tests/database-rollups.test.mjs` covers aggregation types, null/overflow semantics, local formulas, permission-filtered filters/exports, schema isolation, invalid configurations and stale edits, live target updates across replicas and the Chromium build/edit/reload/reader flow, including preserving selected fields while their directory response is delayed.
